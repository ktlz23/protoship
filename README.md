# Protoship — Claude Code MCP Plugin

Turn any AI-generated HTML prototype into a production-ready app in minutes — guided scaffolding, opinionated stacks, and independent code review, all inside Claude Code.

Tell Claude Code *"I have an HTML prototype at `/path/to/app.html`, turn it into a real app"* and it handles the rest.

**No Anthropic API key required.** The plugin is pure I/O — Claude Code does all reasoning, generation, and review using its existing session.

## What it does

1. **Detects in-progress work** — if your previous session was interrupted, picks up where you left off
2. **Reads and analyzes** your HTML prototype (app type, features, data models)
3. **Asks clarification questions** (team skills, budget, integrations)
4. **Recommends a tech stack** with rationale, cost estimate, and alternatives
5. **Checks your machine** for required tools, provides setup instructions for gaps
6. **Scaffolds a complete project** from an opinionated template — real working code, pinned dependencies
7. **Runs an independent quality review** — 3 specialist subagents (security, architecture, code quality) review the code in parallel with no conversation context, like a cold senior-engineer review

## Prerequisites

- Node.js 18+ — [nodejs.org](https://nodejs.org)

That's it. No API key needed.

## Installation

```bash
npx protoship
```

That's it. The installer automatically configures Claude Code and installs the guided workflow skill. Restart Claude Code and say:

*"I have an HTML prototype at ~/Downloads/app.html — help me turn it into a real app."*

## How a session works

You have an HTML prototype generated by an AI tool (ChatGPT, Claude, v0…). You open Claude Code and say:

> *"I have an HTML prototype at `/Users/me/Desktop/my-app.html` — turn it into a real app."*

Claude takes over and guides you through 6 steps:

**Step 0 — Resume detection**
Before anything, Protoship checks if you have an in-progress project from a previous session. If yes, it offers to pick up exactly where you left off instead of starting over.

**Step 1 — Prototype analysis**
Claude reads your HTML file and explains what it found in plain language: the type of app, detected features, and complexity level. It asks a few clarifying questions (your team's skills, budget, integrations needed) before recommending anything.

**Step 2 — Stack recommendation**
Based on your answers, Claude recommends a tech stack with a plain-language rationale, estimated monthly cost, and alternatives. Nothing moves forward until you confirm.

**Step 3 — Prerequisites check**
Claude verifies that all required tools are installed on your machine. If anything is missing, it gives you the exact command to install it — then re-checks before continuing.

**Step 4 — Scaffolding**
Claude generates a complete project: real working code (not stubs), pinned dependencies, environment variable examples, database schema, API routes, and a README with setup instructions. Everything is written to disk. The project state is saved so recovery is possible if the session is interrupted.

**Step 5 — Quality review**
Three independent specialist subagents review the generated code in parallel — security, architecture, and code quality — with no knowledge of your prototype or conversation. You get a score out of 100, a list of issues sorted by severity, and 3 concrete priorities to fix before deploying.

## Available stacks

| ID | Stack | Best for |
|----|-------|----------|
| `nextjs-supabase` | Next.js 14 + Supabase + Vercel | Most SaaS apps — recommended default |
| `nextjs-prisma-neon` | Next.js 14 + Prisma + Neon + Vercel | Complex DB queries, more control |
| `sveltekit-supabase` | SvelteKit + Supabase + Vercel | Simpler syntax, less boilerplate |
| `remix-supabase` | Remix + Supabase + Fly.io | SSR-heavy apps |

## MCP Tools

| Tool | Step | What it does |
|------|------|-------------|
| `protoship_list_projects` | 0 | Lists previously scaffolded projects and their status (for session recovery) |
| `protoship_read_html` | 1 | Reads the HTML prototype and extracts app type, features, and clarification questions |
| `protoship_check_prerequisites` | 3 | Checks that required CLI tools are installed |
| `protoship_get_stack_template` | 2–4 | Returns opinionated stack configs with pinned dependencies, env vars, and scaffold instructions |
| `protoship_write_files` | 4 | Writes the generated project files to disk and saves project state |
| `protoship_read_project_files` | 5 | Reads all project files and returns specialist review checklists for parallel quality review |

Claude handles all analysis, recommendation, code generation, and review orchestration. The tools handle only I/O.

## How the quality review works

After scaffolding, Claude calls `protoship_read_project_files`, then spawns **3 Agent subagents in parallel** — one each for security, architecture, and code quality. Each subagent receives only the project files and its specialist checklist — no conversation history, no HTML context. They review the code as if seeing it for the first time.

Composite score: `security×0.40 + architecture×0.35 + code_quality×0.25`

## Session recovery

If a session is interrupted (closed tab, out of credits, etc.), the plugin automatically detects where you left off:
- Project state is saved to `~/.protoship/projects/` after scaffolding
- `protoship_list_projects` at session start detects in-progress projects
- Review completion is tracked via a `.protoship-review-done` marker file
